# 出问题怎么办 · 救援手册

按症状查。每条都写了**原因**和**怎么修**。

---

## 刷之前先记住这句话

**这套流程不碰 bootloader / modem / persist，所以几乎不可能变砖。**

开不了机 ≠ 砖。砖的意思是连 fastboot 都进不去、插电脑没反应。只要你还能
进 fastboot（音量下 + 电源能出米兔），就一定能救回来。

## 症状 1：`adb devices` / `fastboot devices` 什么都没输出

### 原因（按可能性排序）

1. 数据线只能充电、不能传数据（**最常见**）
2. USB 口问题（前端面板口、USB 3.0 蓝色口有时抽风）
3. Windows 缺驱动
4. Linux 缺 udev 规则
5. 手机不在对应模式（fastboot 状态下 `adb` 当然看不到）

### 怎么修

```bash
# 先看手机在哪个模式
lsusb | grep -E '18d1|2717'
```

| 看到什么 | 说明 |
|---|---|
| `18d1:d00d` | fastboot 模式（用 `fastboot devices`） |
| `18d1:d001` | 系统/恢复模式，但 adb 未授权（看手机屏幕有没有弹窗） |
| `2717:ff40` | 系统已启动，MTP 模式 |
| `2717:0000` 之类 | EDL 深刷模式（罕见，一般是刷坏了） |
| 什么都没有 | 手机没连上 / 线坏了 / 关机了 |

**逐个排除：**

1. **换线**。找一根确定能传文件的（拷过照片的）。
2. **换口**。用主板后面板的 USB 2.0 口（黑色），别用 USB 3.0（蓝色）。
3. **Windows 装驱动**：装 [小米 USB 驱动](https://www.mi.com/service/support/driver/)，
   或者装 MiFlash 会自动带驱动。
4. **Linux 装 udev**：
   ```bash
   sudo tee /etc/udev/rules.d/51-android.rules <<'EOF'
   SUBSYSTEM=="usb", ATTR{idVendor}=="18d1", MODE="0666", GROUP="plugdev"
   SUBSYSTEM=="usb", ATTR{idVendor}=="2717", MODE="0666", GROUP="plugdev"
   EOF
   sudo udevadm control --reload-rules && sudo udevadm trigger --subsystem-match=usb
   ```
   装完**拔线重插**。

## 症状 2：`no permissions (missing udev rules?)`

**只有 Linux 会有。**

### 原因

设备节点属于 `root:root`，你的普通用户没权限读写。

### 怎么修

```bash
ls -l /dev/bus/usb/*/*
# 如果看到 root root 0664，就是这个原因

# 装 udev 规则（同症状 1 第 4 条）
# 然后
sudo udevadm control --reload-rules
sudo udevadm trigger --subsystem-match=usb
# 拔线重插
```

还不行就临时粗暴一点：

```bash
sudo chmod 666 /dev/bus/usb/001/00X    # X 换成实际设备号
```

（重启后失效，治标）

## 症状 3：sideload 卡在某个百分比不动

### 症状

```
serving: 'sagit-RestlessOS-....zip'  (~39%)   ← 停在这儿
Total xfer: 0.85x
```

然后 `adb devices` 空了，`lsusb` 也没有设备了。

### 原因

**USB 掉线。** 不是包坏了，不是手机坏了。

我在自己机器上就是这个症状，实测遇到两次，都在 39% 附近。

### 怎么修

**方案 1：换线换口重来**

换一根粗一点的线（原装线往往最好），插主板后面板 USB 2.0 口。

**方案 2：改用方式 B 拆包直刷**

这是**我最后用的方案**。原因：方式 B 每个分区单独发，掉了可以从断点续，
而且单次传的数据更小（system 分 6 块，每块 500 MB），抗干扰能力强得多。

→ [方式 B · 拆包直刷](刷机方式B-拆包直刷.md)

**方案 3：换台电脑**

有些主机的 USB 控制器就是跟这台手机不对付。换台机器经常就好了。

## 症状 5：开机卡在动画超过 10 分钟

### 原因（按可能性排序）

1. **没做 `twrp format data`**（最常见，我踩过）
2. 数据分区残留旧系统的加密 data
3. vendor 没刷对
4. system 没刷完

### 先看日志（如果还能 adb）

```bash
adb shell "cat /proc/last_kmsg" 2>/dev/null | tail -50
```

或者等它自己重启几次后：

```bash
adb shell "ls /sys/fs/pstore/"
adb shell "cat /sys/fs/pstore/console-ramoops-0" | tail -50
```

### 典型的「没格式化」日志

```
Invalid ext4 superblock on '/dev/block/bootdevice/by-name/userdata'
Failed to mount an un-encryptable, interrupted, or wiped partition at /data: Invalid argument
Service 'bpfloader' (pid 962) exited with status 1
Service bpfloader has 'reboot_on_failure' option and failed
reboot: Restarting system with command 'netbpfload-missing'
```

看到 `bpfloader` + `reboot_on_failure` 就是这个。

### 怎么修

```bash
# 1. 长按电源 15 秒强制关机
# 2. 音量下 + 电源 进 fastboot
# 3. 临时启动 OrangeFox
fastboot boot OrangeFox-24.03.16-Unofficial-sagit.img

# 4. 格式化（关键）
adb shell "twrp format data"
adb shell "twrp wipe cache"

# 5. 确认
adb shell "df -h /data"
# 应该看到 51G

# 6. 重启
adb reboot
```

## 症状 6：fastboot 命令卡住不动

### 症状

- `fastboot flash system ...` 跑了很久没输出
- `Ctrl+C` 也没反应
- 另开终端 `fastboot devices` 也没输出

### 先判断：真卡死还是慢

```bash
# 找 PID
pgrep -af fastboot

# 看读了多少
cat /proc/<PID>/io | grep rchar
```

等 30 秒再看一次：

| rchar 变化 | 进程状态 | 结论 |
|---|---|---|
| 涨了 | R/S | 正常干活，**等** |
| 完全不动 | D | 卡死了，往下看 |
| 已到 3 GB+ | D | 数据发完了，设备在写 eMMC，**等**（实测最后一块要 178 秒） |

### 真卡死怎么救

**第 1 步：杀进程**

```bash
kill -9 <PID>
```

**第 2 步：试 USB 复位（Linux）**

```bash
lsusb | grep -E '18d1|2717'    # 拿到 Bus 和 Device 号
python3 - <<'EOF'
import os, fcntl
fd = os.open('/dev/bus/usb/001/004', os.O_WRONLY)   # 换成你的
fcntl.ioctl(fd, 0x5514, 0)                          # USBDEVFS_RESET
os.close(fd)
print('ok')
EOF
```

> 这个技巧能用是因为 udev 规则把设备节点设成了 0666，普通用户也能 open。

**第 3 步：手机上强制重启（最可靠）**

**长按电源键 15 秒**，直到屏幕黑掉。然后音量下 + 电源重新进 fastboot。

这是**唯一 100% 有效**的方法。我两次都是这么救回来的，数据没有任何损坏。

## 症状 7：刷完开机了，但相机 / 指纹 / 信号不能用

### 原因

vendor 没刷对，或者刷错分区了。

### 怎么查

```bash
# 进系统后（需要先开 USB 调试）
adb shell getprop gsm.version.baseband
# 应该有值，比如 AT20-0506_2249_2f010e6

adb shell ls /vendor/bin/ | head
# 应该有东西，空的说明 vendor 没挂上
```

### 怎么修

重刷 vendor，**注意是 `cust`**：

```bash
fastboot flash cust vendor.img
fastboot erase userdata
fastboot boot OrangeFox-*.img
adb shell "twrp format data"
adb reboot
```

> 常见错误：写成 `fastboot flash vendor vendor.img`。
> 小米 6 没有 vendor 分区，只有 cust。

## 症状 8：想彻底回到原厂 MIUI

### 方法 1：MiFlash 线刷（最干净）

1. 下载 [小米官方线刷工具 MiFlash](https://www.mi.com/service/support/miflash)
2. 下载 MI 6 的[官方线刷包](https://miuirom.org/phones/mi-6)（选 Fastboot 版，约 2.2 GB）
3. 手机关机 → 音量下 + 电源 → fastboot
4. MiFlash 里选包 → 点 Flash
5. **注意**：MiFlash 右下角有"全部删除"/"保留数据"选项，选**全部删除**最干净

> 需要 bootloader 已解锁。刷完仍是解锁状态。

### 方法 2：刷回 LineageOS

如果你有 LOS 的包：

```bash
fastboot flash boot     boot.img
fastboot flash recovery recovery.img
fastboot reboot recovery
# 然后在恢复界面选 Apply update from ADB
adb sideload lineage-22.2-xxxx-sagit-signed.zip
```

## 症状 9：系统能进，但没有 Google Play

### 这不是故障

RestlessOS 是 GrapheneOS 血统，**故意不带 Google 服务**。这是它的核心设计，不是 bug。

### 想要装 App 怎么办

1. **自带 App Store** — 桌面找 `Apps`（包名 `app.grapheneos.apps`，是 GrapheneOS 官方商店）
2. **F-Droid** — 去 <https://f-droid.org> 下 APK 自己装，开源的 App 都在那儿
3. **自己 sideload APK** — 从可信来源下 APK，用文件管理器装

### 想装 Google 服务？

技术上可以（刷 MindTheGapps），但：
- 会破坏这个系统的隐私模型（等于白刷）
- 小米 6 的 A16 GSI 上 GMS 兼容性不保证
- 不建议

## 症状 10：微信 / 支付宝 / 银行 App 说"设备不安全"

### 原因

这些 App 会检查系统完整性（SafetyNet / Play Integrity）。GSI 系统因为
bootloader 已解锁、不是官方签名，通常过不了检查。

### 现实情况

- **微信 / 支付宝**：一般能用，最多提示一下
- **银行 App**：多数直接不让用，或者限制功能
- **游戏（带反作弊的）**：大概率不能玩（原神、王者荣耀可能封号）

### 怎么办

没办法。这是解锁 bootloader 的代价，任何一个第三方系统都一样。

如果这些 App 是刚需，**别刷这个系统**。

## 症状 11：电池掉得快 / 手机发烫

### 原因

1. 老机器（小米 6 是 2017 年的），电池本身衰减
2. 首次开机后系统在做后台优化（正常，一两天就好）
3. 某些 App 在后台跑

### 怎么查

```bash
adb shell dumpsys batterystats | head -50
adb shell top -n 1 | head -20
```

### 缓解

- 设置 → 电池 → 关掉不用的后台
- 关掉「始终允许扫描 WiFi/蓝牙」（设置 → 位置 → 扫描）
- 别装太多国产 App

## 万能救援流程

如果你不确定出了什么问题，按这个顺序试：

```bash
# 1. 能不能进 fastboot？
#    手机：长按电源 15 秒 → 音量下 + 电源
fastboot devices

# 能 → 继续
# 不能 → 手机可能真砖了，尝试 MiFlash EDL 模式（音量下+音量上+电源，插电脑）

# 2. 重新刷一遍
fastboot flash boot    boot.img
fastboot flash system  system-padded.img
fastboot flash cust    vendor.img

# 3. 清干净
fastboot erase userdata
fastboot erase cache
fastboot erase misc

# 4. 格式化
fastboot boot OrangeFox-*.img
adb shell "twrp format data"
adb shell "twrp wipe cache"

# 5. 重启
adb reboot
```

**90% 的问题重刷一遍就好了。**
